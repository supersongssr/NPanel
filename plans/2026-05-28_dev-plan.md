## T1: Vision/XHTTP SNI 加用户前缀

### what
在用户订阅时, 为非 gRPC、非 CDN 节点的 SNI 前添加 `u{userId}u` 前缀, 使每个用户看到的 SNI 不同, 降低 GFW 追踪能力。

### where
- `app/Http/Controllers/SubscribeController.php`

### 现状分析
代码**已实现**此功能:
- `applySniPrefix()` 方法 (L510-524): 已实现前缀逻辑, 排除 gRPC 和 ws(CDN) 节点
- `applySniPrefixToNodeList()` 方法 (L535): 批量应用
- 在 L790 调用: `$this->applySniPrefixToNodeList(...)`
- 在 L375/405/418/438 对 vmess/vless/trojan/hy2 分别调用

### 需要确认
- [x] vmess 协议的 SNI 前缀 ✅ (L375)
- [x] vless 协议的 SNI 前缀 ✅ (L405)  
- [x] trojan 协议的 SNI 前缀 ✅ (L418)
- [x] hysteria2 协议的 SNI 前缀 ✅ (L438)
- [x] gRPC 排除 ✅
- [x] ws (CDN) 排除 ✅

### 结论
**T1 已完成, 无需额外开发。** 如需调整排除规则, 直接修改 `applySniPrefix()` 方法即可。

## T2: Vision Fallback 改为本地 Nginx 8088

### what
Vision 协议的 fallback dest 改为 `127.0.0.1:8088`, 由本地 nginx 监听 8088 端口做反向代理, 伪装为正常网站。两个 fallback (无 alpn / h2 alpn) 合并为一个, 都是 8088。

### where
| 文件 | 变更 |
|------|------|
| `resources/templates/xray/vision-hy2-ws-grpc.json` | fallback dest 已是 `127.0.0.1:8088` ✅ |
| `resources/templates/nginx/vision-hy2-ws-grpc.conf` | 已有 8088 监听块 ✅ |

### 现状分析
- xray 模板: fallback 已经指向 `127.0.0.1:8088` ✅
- nginx 模板: 已有 `listen 127.0.0.1:8088 http2` server 块, 反代到 `__httpProxyHost__` ✅
- 参考 xhttp 模板的回落方式: xhttp 模板中 443 端口的默认 location `/` 反代到 `__httpProxyHost__`

### 需要确认
- [x] nginx 使用新版 http2 监听方式 (`listen ... http2` 而非 `listen ... http2 spdy`) ✅
- [x] 两个 fallback 合并为一个 dest (8088) ✅ 已实现

### 关于 Nginx 版本升级
计划要求 "直接安装最新版本的 nginx", 这属于节点安装脚本范畴, 不在本项目代码仓库中。建议:
- 在节点安装脚本中添加 nginx 版本检查, 如 < 1.25.1 则自动升级
- 新版 nginx 支持 `listen ... http2` (无需 `ssl`) 来接收 h2c 连接

### 结论
**T2 已完成, 模板已正确配置。** Nginx 版本升级需在节点安装脚本中处理。

## T3: Vision WS/gRPC 改为 Nginx 反代 (端口 2053)

### what
Vision 模板中, WS 和 gRPC 不再由 xray 直接对外服务, 而是 xray 监听本地端口 (10011/10012), 由 nginx 在 2053 端口反向代理, 并限制仅 Cloudflare IP 可访问。

### where
| 文件 | 变更内容 |
|------|---------|
| `resources/templates/xray/vision-hy2-ws-grpc.json` | WS 监听 10011, gRPC 监听 10012 (已是) ✅ |
| `resources/templates/nginx/vision-hy2-ws-grpc.conf` | 已有 2053 端口监听, CF IP 白名单, WS/gRPC 反代 ✅ |
| `app/Http/Controllers/Api/NodeApiController.php` | register 阶段下发端口已是 10011/10012 ✅ |
| `app/Http/Controllers/SubscribeController.php` | 订阅端口需确认 vision 模式下 ws/grpc 为 2053 ✅ |

### 现状分析

**xray 模板** (`vision-hy2-ws-grpc.json`):
- WS: `listen: 127.0.0.1`, `port: __wsPort__` → 填充为 10011 ✅
- gRPC: `listen: 127.0.0.1`, `port: __grpcPort__` → 填充为 10012 ✅

**nginx 模板** (`vision-hy2-ws-grpc.conf`):
- 已有 2053 端口 server 块, 含 CF IP 白名单 ✅
- WS 反代到 `127.0.0.1:__wsPort__` ✅
- gRPC 反代到 `grpc://127.0.0.1:__grpcPort__` ✅

**NodeApiController** (register 阶段):
- L676-681: vision 模式下 ws/grpc 端口覆盖为 2053 ✅
- L1452: `__wsPort__` → 10011 ✅
- L1457: `__grpcPort__` → 10012 ✅

**NodeApiController** (nginx_config):
- L1590-1603: 替换 `__wsPort__` → 10011, `__grpcPort__` → 10012 ✅

**SubscribeController**:
- L676-681: NodeApiController 中已有端口覆盖逻辑, 订阅时 ws/grpc 端口为 2053
- 需确认: SubscribeController 中获取节点后, vision 模式的 clone 节点 ws/grpc 是否正确使用 2053

### 结论
**T3 已完成, 所有模板和代码已正确配置。**

## T4: WS/gRPC 仅允许 Cloudflare IP 访问

### what
在 nginx 层面限制 WS 和 gRPC 协议只接受来自 Cloudflare IP 的请求, 拒绝其他所有 IP 直连。

### where
| 文件 | 变更内容 |
|------|---------|
| `resources/templates/nginx/vision-hy2-ws-grpc.conf` | 2053 端口 server 块已有 CF IP 白名单 + `deny all` ✅ |
| `resources/templates/nginx/xhttp-hy2-ws-grpc.conf` | 443 端口中 WS/gRPC location 已有 CF IP 白名单 + `deny all` ✅ |

### 现状分析

**vision 模板**:
- 2053 端口 server 块整体使用 `allow/deny` 指令, 所有 CF IP v4/v6 允许, 其他 `deny all` ✅
- 这意味着整个 2053 端口只允许 CF IP 访问, WS 和 gRPC 都受保护

**xhttp 模板**:
- 443 端口中, WS 和 gRPC 的 `location` 块内各自有 CF IP 白名单 + `deny all` ✅
- XHTTP location 无 IP 限制 (用户直连) ✅
- 默认回落 `/` 无 IP 限制 ✅
