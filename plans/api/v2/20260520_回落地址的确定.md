# 回落地址配置方案

## 问题

`NodeApiController` 中三个模板占位符的值目前是硬编码的：

| 占位符 | 当前硬编码值 | 正确值 | 模板用法 |
|--------|-------------|--------|---------|
| `__httpProxyHost__` | `npanel-nav.freessr.bid` | `npanel-nav.freessr.bid` | `proxy_pass http://__httpProxyHost__;` hostname only |
| `__v2Fallback__` | `127.0.0.1` | `remote-npanel-nav.freessr.bid` | `"dest": "__v2Fallback__:8001"` hostname only |
| `__HYSTERIA_URL__` | `https://www.bing.com` | `http://npanel-nav.freessr.bid:80` | `"url": "__HYSTERIA_URL__"` full URL |

## 推导关系：一个配置项即可

三者均可从一个基础域名 `node_fallback_host` 推导：

```
node_fallback_host = "npanel-nav.freessr.bid"

__httpProxyHost__ = node_fallback_host                          → npanel-nav.freessr.bid
__v2Fallback__    = "remote-" + node_fallback_host              → remote-npanel-nav.freessr.bid
__HYSTERIA_URL__  = "http://" + node_fallback_host + ":80"      → http://npanel-nav.freessr.bid:80
```

因此只需在 `config` 表中存储一条 `node_fallback_host` 配置。

## 涉及文件

```
修改:
  app/Http/Controllers/Api/NodeApiController.php    # 读取配置，推导三个占位符的值
  resources/views/admin/backend.blade.php            # 新增"回落配置" tab

新增:
  database/migrations/2026_05_20_000000_add_fallback_config.php  # 插入 config 行
```

> 不需要修改 `AdminController.php`：`backend()` 已将 `Helpers::systemConfig()` 的全部键作为变量传入视图，新增的 `node_fallback_host` 自动可用。

## Step 1: Migration — 插入 1 条 config 记录

```php
// database/migrations/2026_05_20_000000_add_fallback_config.php

class AddFallbackConfig extends Migration
{
    public function up()
    {
        Config::firstOrCreate(
            ['name' => 'node_fallback_host'],
            ['value' => 'npanel-nav.freessr.bid']
        );
    }

    public function down()
    {
        Config::where('name', 'node_fallback_host')->delete();
    }
}
```

**白名单无需额外处理**：`AdminController::setConfig()` 通过 `array_key_exists($name, self::$systemConfig)` 校验，而 `self::$systemConfig` 来自 `Helpers::systemConfig()` — 它加载 `config` 表所有行。migration 插入后该 key 自动可保存。

## Step 2: NodeApiController — 从配置推导替换硬编码

### 2a. `config()` 方法（第 1388 行起）

在方法内添加 `$sysConf = Helpers::systemConfig();`，然后修改 `$vars` 数组：

```php
$fallbackHost = $sysConf["node_fallback_host"] ?? "npanel-nav.freessr.bid";

$vars = [
    // ...existing...
    "__v2Fallback__"    => "remote-" . $fallbackHost,
    "__HYSTERIA_URL__"  => "http://" . $fallbackHost . ":80",
    // ...existing...
];
```

### 2b. `nginxConfig()` 方法（第 1530 行起）

在 `str_replace` 调用前添加：

```php
$fallbackHost = Helpers::systemConfig()["node_fallback_host"] ?? "npanel-nav.freessr.bid";
```

然后在替换数组中将硬编码值改为 `$fallbackHost`。

### 3c. JavaScript

```javascript
// --- Fallback Config ---
$(function() {
    var $input = $("#input_node_fallback_host");
    function updatePreview() {
        var host = $input.val().trim() || 'npanel-nav.freessr.bid';
        $("#preview_http").text(host);
        $("#preview_v2").text("remote-" + host);
        $("#preview_hy2").text("http://" + host + ":80");
    }
    $input.on("input", updatePreview);
    updatePreview();
});

function saveFallbackHost() {
    var host = $("#input_node_fallback_host").val().trim();
    if (!host) {
        layer.msg('域名不能为空', {time: 2000});
        return;
    }
    $.post("/admin/setConfig", {
        _token: '{{csrf_token()}}',
        name: 'node_fallback_host',
        value: host
    }, function (ret) {
        layer.msg(ret.message, {time: 1000});
    });
}
```

## 变更影响范围

- **新节点**：注册后首次拉取配置即使用数据库值
- **已有节点**：下次调用 `GET /api/node/config` 或 `GET /api/node/nginxConfig` 时自动使用新值
- **无需重启**：`Helpers::systemConfig()` 每次从 DB 实时读取

## 执行顺序

1. 创建并运行 migration → config 表写入 `node_fallback_host` 记录（默认值 `npanel-nav.freessr.bid`）
2. 修改 `NodeApiController::config()` 和 `nginxConfig()` → 从配置推导三个占位符值
3. 修改 `backend.blade.php` → 新增"回落配置" tab（含实时预览）
4. 测试：Admin 页面保存、节点配置下发验证
