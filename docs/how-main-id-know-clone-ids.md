# NPanel 主节点与克隆节点映射关系报告

## 1. 核心映射关系
在 NPanel 系统中，一个主节点（Main Node）与多个克隆节点（Clone Nodes）通过数据库字段建立了一对多的逻辑关系。

### A. 逻辑链接字段 (`is_clone`)
- **定义**：在 `ss_node` 表中，`is_clone` 字段记录了该节点的“归属”。
- **主节点**：`is_clone = 0`。
- **克隆节点**：`is_clone = {主节点ID}`。
- **查询方式**：
  ```sql
  -- 查找主节点 156 的所有子节点
  SELECT id, name, v2_name, ip FROM ss_node WHERE is_clone = 156;
  ```

### B. ID 序列封存 (`node_ids`)
- **定义**：为了方便前端和订阅系统快速调用，主节点的 `node_ids` 字段会以逗号分隔的形式存储自己及其所有克隆节点的 ID。
- **示例**：若主节点 ID 为 156，它有三个子节点 157, 158, 1097，则主节点的 `node_ids` 为 `"156,157,158,1097"`。

---

## 2. 如何识别每个 Clone ID 的配置？
克隆节点本质上是主节点在不同协议或 IP 栈下的“影子”。你可以通过以下三个维度识别其具体配置：

### A. 协议类型 (`v2_name`)
克隆节点的 `v2_name` 字段不再存储协议组（如 `xhttp-hy2-...`），而是存储**单一的具体协议**。
- 如果 `v2_name = "xhttp"`，则该 ID 专门负责处理 xhttp 流量。
- 如果 `v2_name = "hy2"`，则该 ID 负责 Hysteria2。

### B. 节点名称 (`name`)
系统在注册时会自动生成易读的名称，格式为：
`{主节点名} - {协议名} ({IP类型})`
- **示例**：`Singapore-NorthWest - xhttp (ipv4)`

### C. 网络协议与地址
- **IPv4/IPv6**：通过查看 `ip` 和 `ipv6` 字段。通常一个克隆节点只开启其中一个地址。
- **Server 地址**：每个克隆节点都有独立的 `server` 字段（如 `node157.ssmail.win`），其解析记录对应其特定的 IP。

---

## 3. 快速对账手册 (Knowing the Config)

如果你知道主节点 ID，可以通过以下步骤查询所有克隆节点的配置图谱：

| 步骤 | 操作 | 目的 |
| :--- | :--- | :--- |
| **1** | 读取主节点的 `node_ids` | 获取整组节点的数字清单 |
| **2** | 遍历清单中的 ID | 区分主 ID（通常是第一个）和子 ID |
| **3** | 查看子 ID 的 `v2_name` | 确定该节点承载的**代理协议** |
| **4** | 查看子 ID 的 `ip` / `ipv6` | 确定该节点承载的**网络栈** |

## 4. 总结
- **主 ID** 是配置的“源头”，存储了所有的原始元数据。
- **Clone ID** 是执行的“触角”，每个 Clone ID 锁定 **“一个特定协议 + 一个特定 IP”**。
- **映射核心**：`is_clone` 字段是寻找归属的唯一索引，`node_ids` 是快速遍历的工具。
