# 节点驱动状态同步方案 (Node-Driven State Sync Plan)

## WHAT
实现一种以节点端为“真理源”的状态同步机制。
- **注册阶段 (Register)**：面板端实行“镜像覆盖”策略。节点上报的字段（如 `node_id`, `node_ids`, `root_domain`, `v2_name` 及缓存流量）优先采用；未上报的字段一律按默认值处理/清空。
- **状态阶段 (Status)**：面板端下发丰富的状态 JSON，供节点端缓存并展示，形成闭环。

## WHY
1. **防止流量丢失**：解决软重装过程中，面板端因缺少初始基准而导致的流量统计断层。
2. **逻辑极致简化**：通过“上报即覆盖，不上报即重置”原则，彻底解决旧节点回收（Recycle）时残留脏数据的问题。
3. **数据透明化**：让节点端实时掌握本周期的精准剩余流量、当日使用量等核心指标。

## WHERE
1. **`app/Http/Controllers/Api/NodeApiController.php`**：
    - `register` 接口：重构字段处理逻辑，支持强制覆盖与默认值回退。
    - `status` 接口：增强返回内容，包含详细的流量统计指标。


## HOW
### 1. 增强的 Status 响应
面板在 `status` 接口必须返回包含以下字段的 JSON：
- `traffic_used`: 本周期已用总流量。
- `traffic_left`: 本周期剩余总流量。
- `traffic_used_daily`: 今日已用流量。
- `traffic_left_daily`: 今日剩余配额（如有）。

### 2. 节点主导的 Register 逻辑
`proxyInstall.sh` 在执行注册时，必须优先使用以下信息：
- 基础识别：`node_id`, `node_ids`, `root_domain`, `v2_name`。
- 流量缓存：由 `status` 阶段保存的 `traffic_used`。
- 网卡基准：当前的 `raw_rx`, `raw_tx`。
没有携带的信息, 请使用 默认值. 清除掉 旧节点的一些缓存的信息! 这些很重要.

### 3. 面板端的镜像覆盖逻辑
在 `NodeApiController@register` 中：
- **优先采用原则**：如果请求中包含上述字段，直接更新数据库。
- **不上报即清空**：对于旧节点（被回收重新分配的节点），如果节点端没有上报某些可选配置信息，面板端必须将其设为默认值或 NULL，确保环境纯净。
- **基准初始化**：根据上报的 `raw_rx/tx` 立即初始化 `last_raw_total`，确保注册后的首次上报增量准确。

## MUST
1. **信任上报流量**：在注册时，必须以节点上报的 `node_traffic_used` 作为 DB 初始化值。
2. **字段全清逻辑**：必须在代码中显式处理所有 SsNode 的配置字段，实现“未提及则重置”。
3. **状态闭环**：`status.sh` 必须具备解析并保存面板下发流量信息的能力。
4. **幂等安装**：确保无论是在新系统安装，还是在旧系统覆盖安装，最终面板端的节点状态都与 `.env` 的声明完全一致。
