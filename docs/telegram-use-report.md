Telegram 使用分析报告

  ★ Insight ─────────────────────────────────────
  这是一个轻量级、单向通知型的 Telegram 集成，没有使用任何第三方 SDK，而是直接通过 HTTP 调用 Telegram Bot
  API。设计上偏向"够用就好"——仅在关键业务事件时推送消息给管理员。
  ─────────────────────────────────────────────────

  ---
  1. 核心组件

  ┌─────────────────────────────────────────┬────────────────────────────────────────────────────┐
  │                  文件                   │                        作用                        │
  ├─────────────────────────────────────────┼────────────────────────────────────────────────────┤
  │ app/Components/Telegram.php             │ 主服务类，封装 send() 发送消息 + addLog() 记录日志 │
  ├─────────────────────────────────────────┼────────────────────────────────────────────────────┤
  │ app/Components/Curl.php                 │ HTTP 客户端，负责实际调用 Telegram Bot API         │
  ├─────────────────────────────────────────┼────────────────────────────────────────────────────┤
  │ app/Http/Controllers/UserController.php │ 唯一的调用方，在两处触发通知                       │
  └─────────────────────────────────────────┴────────────────────────────────────────────────────┘

  2. 配置方式

  配置存储在数据库 config 表中（非 .env 文件），包含三个键：

  ┌────────────────────┬─────────────────────────────────┐
  │       配置键       │              说明               │
  ├────────────────────┼─────────────────────────────────┤
  │ is_telegram        │ 开关（启用/禁用）               │
  ├────────────────────┼─────────────────────────────────┤
  │ telegram_bot_token │ Bot Token（从 @BotFather 获取） │
  ├────────────────────┼─────────────────────────────────┤
  │ telegram_chat_id   │ 接收通知的 Chat ID              │
  └────────────────────┴─────────────────────────────────┘

  管理后台入口：resources/views/admin/system.blade.php (行 682-710)，提供可视化配置界面。

  3. 业务触发点

  在 UserController.php 中有 两处 调用：

  - 行 1134 — 邀请返利提现申请时推送通知
    - 标题：🎉 邀请返利提现申请
    - 内容包含：用户名、ID、提现金额、待审核状态
  - 行 1243 — 消费返利提现申请时推送通知
    - 标题：💰 消费返利提现申请
    - 内容格式同上

  4. 通知日志

  所有 Telegram 通知通过 addLog() 方法记录到 email_log 表，以 type = 3 区分（该表同时存储邮件等其他通知类型）。

  5. 架构总结

  用户发起提现 → UserController → Telegram::send()
                                      ↓
                                组装 Markdown 消息
                                      ↓
                           检查配置（token/chat_id/开关）
                                      ↓
                           Curl::send() → Telegram Bot API
                                      ↓
                           addLog() → email_log 表 (type=3)

  7. 潜在改进点

  1. 配置应迁移至 .env — Bot Token 和 Chat ID 属于敏感凭据，目前存在数据库中，不符合 Laravel 最佳实践（config/telegram.php + env()
   读取）
  2. 缺少重试/队列机制 — send() 是同步调用，若 Telegram API 超时会阻塞用户请求。可改用 Laravel Queue + Job 异步发送
  3. 仅支持单一 Chat ID — 无法同时通知多个管理员/群组
  4. 无消息模板化 — 两条通知的消息体几乎相同，可提取为模板方法
  5. 错误处理较简单 — 发送失败时仅记日志，无告警升级机制
